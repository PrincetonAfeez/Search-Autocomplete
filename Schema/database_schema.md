# Database Schema

## Table: `corpus_word`

Represents one searchable corpus term used to build the in-memory autocomplete trie.

| Field | Type | Required | Constraints | Purpose |
| --- | --- | --- | --- | --- |
| `id` | integer | yes | Primary key, generated by Django | Stable database identifier. |
| `text` | string | yes | Max length: 255; stripped before save; must not normalize to blank | Display text shown to users. |
| `normalized_text` | string | yes | Max length: 255; unique; indexed; generated from `text`; not directly editable | Case-insensitive lookup key and duplicate guard. |
| `weight` | integer | yes | Default: 1; minimum: 0; maximum runtime limit: 2,147,483,647 | Ranking score; higher values rank earlier. |
| `is_active` | boolean | yes | Default: true | Controls whether the word is loaded into the autocomplete engine. |
| `created_at` | datetime | yes | Auto-created | Creation timestamp. |
| `updated_at` | datetime | yes | Auto-updated | Last update timestamp. |

## Ordering

Default ordering is ascending `normalized_text`.

## Cache invalidation rule

Changes to corpus rows invalidate the in-memory autocomplete engine so the trie can be rebuilt from active records.

## Derived runtime shape

Active rows are loaded as `(text, weight)` pairs and inserted into the trie. The trie is a runtime index and is not persisted as a database table.
